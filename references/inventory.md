# 工程盘点契约

扫描 JSON 保持 version: 1，保留 files / groups / imports / edges 的原有含义，并增加下列字段。旧消费者可以忽略新增字段。

- inventory：已识别源码与分析配置的统一清单。每项包含 id/path、语言、类别、分类规则、大小、内容指纹、捕获/计数/解析状态与逐文件指标。不支持引用解析、超限、变化和读取失败的文件仍在清单中。源码正文仍只在 files 内提供，配置仅输出必要声明片段。
- metrics：scc 工具版本/状态，以及按类别、语言、目录汇总的 code/comments/blanks/lines/files/countedFiles。按路径去重，不按相同内容合并不同文件。工具不可用或一组文件没有可用计数时指标为 null；部分成功的汇总标记 partial，不能作为完整总量。
- technologies：识别规则版本在分析指纹中固定；按技术 ID 合并声明、锁文件记录、源码引用与语言证据。每条证据含相对路径、定位、相关片段；声明与锁定值另有 selector 精确定位。npm 支持 v2/v3 packages 结构，uv 多版本全部列为候选并注明未求值环境标记。无有效锁文件时不补版本；vendor 清单和引用不用于推断项目技术栈。
- coverage：计数与解析各自独立的分母、成功数和状态分布；盘点与解析预算、分类规则也保留在此处。范围限定为识别规则支持的源码扩展名；未知扩展名不伪装成完整覆盖。Git 忽略项及依赖安装、构建、运行目录排除。
- coverage.parsingTool：本次 JS/TS 分析选择的 Node 状态、可执行文件路径及版本；没有 JS/TS 待解析输入时为 null。自动查找逐个验证 PATH 候选，显式 --node 不做回退。该运行时信息纳入分析指纹；工具恢复后重扫不会复用旧的不完整快照标识。
- snapshot.analysisInputHash：盘点文件内容指纹、配置与锁文件、分类/技术识别规则、计数工具及解析规则版本的指纹；snapshot.id 使用其前缀。sourceHash 仍用于捕获的源码输入，mappingHash 独立反映架构成员。相关配置变化需重扫。
- groups[].stats：成员集合去重后的全部/自有源码统计，以及入向/出向引用处数（以 from/to/line 去重）。只汇总已解析的跨成员集合引用，不是运行时调用次数。

类别按第三方目录 > 生成目录或文件头标记 > 测试/夹具目录或文件名 > 常规自有源码确定。自有表示当前规则的默认类别，不作版权判断；规则未覆盖的生成代码可能仍计入该类别，发现时应修订确定性规则并重扫。

捕获的文件写入独立临时目录供 scc 分析，不执行项目配置、脚本或构建命令。扫描末尾核对原始输入；变化的文件清空计数并移除相关引用、技术识别依据，标记 changed 待重扫。扫描器不提供任意路径读取接口。工具缺失不使用 AI 或另一种口径静默补值。

可选参数：scan.py 和 serve.py 均支持 --scc 与 --work-dir；原有参数保持兼容。依赖预检：python3 scripts/preflight.py [--node /path/to/node] [--scc /path/to/scc]。其他平台需自行准备 scc；本工具不会在扫描时联网安装。
