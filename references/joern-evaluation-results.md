# Joern 三层代码浏览验证结果

日期：2026-10-28（Asia/Shanghai）。对象：固定 Joern 4.0.666、Temurin JDK 21.0.13+9、macOS arm64。

## 结论：适合作为可选增强

Joern 能在禁网环境中为 JS/TS 和 Python 建立可查询的 CPG，提供函数、参数、局部绑定、调用候选、控制流及数据依赖。**本次结果不支持把它直接设为三层代码浏览的唯一核心引擎。**

主要依据是：多层再导出未定位到源码实现，提前 return 的 CFG 未体现 finally 清理，默认文件过滤与 CodeStrata 的盘点范围不同，以及原始 IR 绑定/引用不能直接当作源代码变量的完整定义与引用。

建议第一版继续使用 TypeScript 和 Python 的语言工具建立源代码身份、定义与引用；Joern 作为显式启用的后台深度分析能力。系统架构 → 文件 → 函数 → 逻辑的交互方向仍然可行，本轮没有改造正式看板或正式扫描 API。

## 实测范围与成本

所有 Joern 子进程通过 macOS sandbox-exec 禁止网络。输入来自现有 inventory 的捕获快照，不运行目标项目、安装其依赖或修改其代码。JVM 堆上限 4 GiB；时间包含启动及监测，重复索引是两次独立构建，**不是增量索引测试**。

| 输入 | JS/TS 输入文件 | Python 输入文件 | JS/TS 两次索引 | Python 两次索引 |
|---|---:|---:|---|---|
| 最终语言根目录夹具 | 4 | 4 | 2.63 / 4.22 秒 | 2.61 / 2.09 秒 |
| CodeStrata 捕获快照 | 16 | 29 | 4.83 / 4.26 秒 | 7.03 / 8.18 秒 |
| Future Props Lab 捕获快照 | 2,470 | 1,125 | 53.19 / 77.01 秒 | 49.61 / 50.60 秒 |

真实大项目运行期间存在其他验证活动；这些数值描述本机实测，不作为产品延迟承诺。

| Future Props Lab 指标 | JS/TS | Python |
|---|---:|---:|
| 每次索引 CPG 大小 | 约 77.7 MiB | 约 63.4 MiB |
| time 记录的阶段最大 RSS | 约 4.34 GiB | 约 4.57 GiB |
| 有界原始导出 | 约 39.9 MiB | 约 25.9 MiB |
| 同会话局部查询 P50 | 0.781 ms | 0.321 ms |
| 同会话局部查询 P95 | 5.599 ms | 5.403 ms |
| 同会话局部查询最大值 | 36.257 ms | 26.397 ms |

查询每语言固定 20 个样本，P95 使用 nearest-rank。测量的是已加载 CPG 中的调用上下游、标识符、控制结构和参数查询，不包括进程启动、索引、传输、布局或浏览器渲染。样本不是随机准确性调查。

Joern 解压后约 **1.87 GiB**，JDK 约 **0.33 GiB**，另保留约 1.82 GiB 下载归档。堆上限不等于进程总 RSS；计时器和进程树抽样的口径也不同，原始记录均保留。

官方完整 GraphSON 导出在约 17.6 MB 的 JS/TS 输入上超过 **12 GB**，实验已主动中断，未继续整图加载。该大文件作为成本观察保留，不作为完整可用 JSON 证据。随后改为全局声明索引加局部函数体导出：默认大项目选取 40 个方法，详细节点上限 50,000；核心关系 200,000 条、数据依赖 50,000 条，分别记录范围与截断。即使有界结果也不应整个传给浏览器，正式服务需要焦点查询。

## 能力与缺口

### 函数调用

双语言各有 10 个带源码预期的调用定位案例。最终两种语言均为 **4 个定位到预期内部实现、6 个未定位到内部实现，未发现本组预期中的错误内部目标**。

- 普通直接导入对照、同文件嵌套调用、递归、finally 中的 cleanup 调用可定位。
- 经 barrel 再导出的别名、函数、构造和方法等案例未连接到真实实现；原始 CPG 中可见对应的外部占位目标。
- 已补充显式构造函数，避免将并不存在的源码构造函数写入预期。
- 语言根目录对照仍出现上述结果，不能仅归因于最初的双语言目录布局。
- 未知回调和动态目标保留未解析，没有用同名匹配补出确定连线。

这组夹具故意集中测试再导出等困难情况，多个失败共享同一导入链原因；**4/10 不能当作一般项目的调用图准确率**。

### 变量与数据依赖

同名局部绑定可以分开提取，局部变量名、参数、作用域和原始 REF 关系可获得。但全局/闭包代理绑定、声明处引用、解构容器及降级后同一位置的重复 IR 需要归一化。

在独立的“先写 1、再写 2、最后读取 value”夹具中，两种语言的 REACHING_DEF 都连接最后一次写入到读取，没有把被覆盖的第一次写入直接连接到该读取。这证明该具体能力有用，不证明任意跨函数或对象别名数据流均准确。

CodeStrata 的每语言 20 处实际调用、10 个实际赋值/绑定已逐项按快照源码核对：各含 10 个内部候选与 10 个未解析调用。所选内部候选与源码定义一致；未解析组主要是平台、标准库和外部依赖。变量声明/绑定位置可在原文中确认，但 JS/TS 10 个绑定中 8 个、Python 10 个绑定中 6 个发现引用不完整或同位置 IR 重复等问题。**这是确定性选样下的适配检查，不是总体准确率。**

检查由 Codex 按源码完成，记录了路径、行号、上下文、目标与逐项结论；不是用户人工确认，也不是运行验证。

### 控制流

关键反例已保存为可重复检查：

- JS/TS：worker.ts 第 46 行 `return total` 的 CFG 直接后继为 METHOD_RETURN；未经过第 51 行 cleanup。
- Python：worker.py 第 67 行 `return total` 的 CFG 直接后继为 METHOD_RETURN；未经过第 72 行 cleanup。

源码语言语义要求 return 前执行 finally；该结果未表示这条清理路径。因此不能把当前 CFG 直接称为完整、精确的函数执行流程。AST 中存在 finally 或识别出 cleanup 调用，不等于 CFG 已正确表示清理行为。JS/TS 的 break/continue 还出现 order fallback 日志。

循环、提前返回、异常、异步及生成器结构均进入夹具；本轮没有验证任意挂起/恢复、取消、异常传播等完整运行语义，预览应采用带范围说明的结构化逻辑图。

### 范围与失败状态

Future Props Lab 输入的 JS/TS 2,470 个文件中，导出声明索引出现了 1,544 个文件；未出现的 926 个按现有分类为测试 505、第三方 396、自有源码 24、生成代码 1。自有遗漏包含文档中心源码及声明文件。Python 1,125 个输入文件都出现文件节点。

这里的“出现文件节点”不表示语法有效、每个函数都展开或全部语义正确；Joern 的默认过滤与现有 inventory 不同，未出现的文件不能统一解释为解析失败。若接入产品，必须对齐配置并逐文件说明差异。

负向夹具中，Joern 在坏语法存在时仍能返回成功：JS/TS 缺少对应文件，Python 还可能保留文件节点。实验命令因此加入独立 TypeScript/Python 语法检查，标记 invalid-source 和缺失范围。缺少依赖的调用保留未解析。

真实 1 秒 Joern 预算测试中，两种语言均被标为 timeout；捕获后修改的一次性项目副本被标为 changedInputs，`validForCurrentProject` 为 false。没有修改真实输入项目来测试变化。
